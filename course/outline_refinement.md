## 开场：从零散工具转向完整工作流

- **口播主线：** 讲者认为，许多 AI 科研分享只介绍单个 Skill 或单项任务，较少讲清楚各阶段如何衔接；本次分享按文献管理、研究构思、写作、数据分析与绘图、成果展示和论文追踪展开，也提醒听众留意 AI 辅助研究中的局限。
- **听众预期：** 先给出讲者认为综合能力较强的五类学术 Skill，再沿论文工作流程介绍工具和用法，最后回到人工阅读、判断和核验。

## 第一章：综合能力较强的五个学术 Skill

**本章重点：** 先建立工具地图，说明五个 Skill 各自覆盖什么任务、适合什么研究场景；口播稿中的“最强”等说法是讲者的个人评价。

### 1.1 Scientific Agent Skills

- **工具与用途：** 讲者把它描述为覆盖面较广的科学工具包，包含科学计算、Python 科学工具、数据分析和可视化能力。
- **适用场景：** 重点举自然科学、生物医学和化学研究为例。
- **口播重点：** 强调它面向一组科研任务，而不是只处理单一环节。

### 1.2 Nature Skills

- **工具与用途：** 口播稿称其包含 15 个 Skill，覆盖研究观点或选题的寻找、文献调研、论文写作和科研绘图。
- **适用场景：** 讲者特别提到希望撰写 Nature 方向论文的听众。
- **口播重点：** 将它作为覆盖论文多个阶段的综合工具介绍；Skill 数量和能力范围按讲者原话呈现。

### 1.3 Academic Research Skill

- **工具与用途：** 通过苏格拉底式问答持续追问、质疑研究设想。
- **适用场景：** Idea 提炼和论文架构改进。
- **口播重点：** 讲者分享自己偏好这种反复讨论方式，认为它能帮助研究者审视论点。

### 1.4 Codex Auto Research

- **工具与用途：** 口播稿介绍其反复辅助实验、调整参数、分析数据和运行脚本。
- **适用场景：** 计算机科学和人工智能研究。
- **口播重点：** 将其定位为偏实验和脚本执行的研究辅助工具。

### 1.5 Codex Cloud Academic Skills

- **工具与用途：** 口播稿称它对中文用户较友好。
- **适用场景：** 中文论文，以及偏人工智能方向的论文。
- **转写提醒：** 后文另出现“Cortex Cloud Academic Skills”，与本节名称不一致，保留原稿写法，待核实。

## 第二章：文献管理

**本章重点：** 口播稿把文献工作分成三条线：用 Codex Skill 检索、使用专门的 AI 文献调研网站、把 Codex 与个人文献库连接起来；同时用可视化工具辅助发现论文关系。

### 2.1 用 Codex Skill 检索文献及其局限

- **提到的工具：** Academic Research、Science Direct Live Session Fetcher。后一个名称按口播稿原样保留。
- **口播描述的用法：** 下载 Skill 后让它在网页上寻找文献；一些流程会通过浏览器打开网页并点击 PDF 下载按钮。
- **讲者提出的局限：** 检索结果可能不完整，有时只能看到标题或摘要；部分论文网站的反爬限制较强，需要浏览器操作和相应权限，逐篇点击下载效率较低。
- **讲述提醒：** 讲者因此不推荐把这类方式作为大规模文献调研的主要方法。保留他对方法的评价，不扩展为所有 Skill 或网站都必然如此。

### 2.2 用 AI 文献调研网站开展专题调研

- **提到的网站：** “Undermen”（稿中也出现“Undermind”“Andamard”，名称转写不一致，待核实）、“alicit”，以及另一个未清楚报出名称的网站。
- **口播描述的流程：** 先说明待调研的论文或主题；回答网站关于文献覆盖边界、调研优先服务目标等问题；查看初步调研草稿；通过继续对话收紧范围；启动调研并阅读报告与文献列表。
- **讲者演示内容：** 讲者称一次调研在不到十分钟内找到约 203 篇文献，并展示可打开 PDF 或网页阅读的结果。该数量、耗时和对结果可靠性的评价均为口播稿中的演示陈述。
- **后续整理：** 讲者还演示让网站协助梳理论文架构和后续需要补充的内容；他认为其论文撰写能力有限，后续写作任务会转回 Codex。
- **讲述提醒：** 第三个网站没有清晰名称，不补猜；对检索完整性、文献真实性等评价按讲者观点介绍。

### 2.3 用文献关系图和可视化工具找关联

- **Connected Papers：** 输入一篇论文，查看相关论文之间的关系网络，用于发现关联文献。
- **Resource Rabbit：** 导入文献库，查看库内论文关系，也可查看作者之间的关联。
- **Lip Maps：** 口播稿称其提供多种文献可视化图表；名称可能存在转写疑点，原样保留。
- **口播重点：** 把这些工具作为辅助发现论文关系的小工具，与 AI 调研和研究者自行判断配合使用。

### 2.4 将 Codex 连接到 ZikTaro 文献库

- **名称说明：** 文献库名称在口播稿中出现“ZikTaro”“Ztero”“Zitero”等不同写法；本节用“ZikTaro”指代该库，并注明名称待核实。
- **口播描述的连接步骤：** 在插件商店搜索该工具、安装并完成连接。稿件没有交代具体插件名称、配置字段或权限步骤，不在提纲中补写。
- **连接后的示例：** 让 Codex 读取文献库中某研究方向的论文，整理整体研究脉络、逐篇摘要，并生成其他报告或候选投稿方向。
- **工作流：** 在文献调研网站开展较大范围的检索 → 将筛选出的论文保存到文献库 → 让 Codex 读取文献库并协助总结、整理和引用。
- **口播重点：** 讲者把文献库作为可追踪的资料来源，强调调研结果与个人文献管理之间的衔接。

## 第三章：Idea 与论文架构

**本章重点：** 研究构思需要围绕研究问题、研究缺口和论文核心主张反复澄清；口播稿推荐以相关论文为依据开展多轮问答。

### 3.1 明确核心主张和研究缺口

- **工具：** 主要使用 Academic Research Skill 的苏格拉底式追问方式。
- **讨论内容：** 研究者最希望读者相信的核心主张是什么；如果只能保留一个创新点会选什么；所谓的 gap 究竟是工具缺口、设计相关缺口还是用户理解缺口。口播稿将中间一类转写为“设计视觉管”，具体所指待核实。
- **口播重点：** 通过把宽泛的 Idea 拆成可解释、可讨论的问题，检查研究论点是否清楚。

### 3.2 通过多轮问答打磨 Idea

- **口播描述的用法：** 把论文 Idea 交给 Skill 讨论，逐轮回答它提出的问题，再进入下一轮追问。
- **问题示例：** 追问研究流程的核心贡献（口播稿此处疑似转写为“核心充电”）；例如继续追问“如果没有手机端，也能做这件事吗”。示例用于说明质疑方式，不预设具体研究结论。
- **讲者经验：** 讲者称一个 Idea 可能需要七八轮讨论才逐渐成熟。
- **讲述提醒：** 呈现为辅助审视和论证的过程，研究者仍需决定哪些意见成立。

### 3.3 先读最相关的论文，再讨论 Idea

- **口播建议：** 先找约 10 至 20 篇最相关论文，放入 ZikTaro 文献库或本地文件夹，再让 AI 详细阅读这些材料后参与讨论。
- **讲者给出的理由：** 不同学科和具体研究方向在方法、写作方式和论文结构上差别很大；提供领域相关论文有助于后续讨论贴近研究背景。
- **讲述提醒：** 数量为讲者给出的建议范围，不扩展为固定标准；名称异写沿用第二章的说明。

### 3.4 从研究构思过渡到论文架构

- **口播描述的衔接：** 在明确研究问题并梳理相关文献后，继续讨论论文整体架构，以及研究者还需要补充的内容。
- **可展示的操作：** 结合上一章中讲者让文献调研网站协助梳理论文架构和待补充内容的示例，再转入 Codex 侧的论文构思与写作辅助。
- **口播重点：** 架构应服务于研究主张和领域文献，不把 AI 生成的框架直接当作最终结构。

## 第五章：数据分析与科研绘图

**本章重点：** 区分生成式图像提供构图参考，与使用真实数据和绘图工具制作可用于论文的图表。口播稿同时提及科学 Skill、Python、HTML 和排版工具。

### 5.1 用科研 Skill 辅助数据分析

- **提到的工具：** Nature Skills；口播稿此处另写作“Nature Scale”，名称转写疑点待核实。
- **口播描述的用途：** 协助数据分析和科研绘图；讲者称现有 Skill 在这类任务上能力较强。
- **讲述重点：** 作为科研工作流的辅助能力介绍，不扩写具体分析方法或数据类型。

### 5.2 用生成式图像探索构图

- **口播描述的做法：** 用图像生成模型先生成 workflow 一类的整体示意图，观察构图和视觉表达。
- **使用边界：** 讲者明确提醒，这种直接生成的完整图不能直接作为正式论文图；可用于构图参考，图中元素和图标需要后续手动绘制或用 HTML 等方式排出。
- **口播重点：** 说明它是视觉构思的参考来源，不等同于基于研究数据绘制的论文图表。

### 5.3 用真实数据和绘图工具制作图表

- **口播描述的做法：** 使用 Python 根据实际数据绘图，再用 HTML 或绘图、排版类 Skill 组合和完善图表。
- **口播示例：** 展示按数据绘制并排版的论文图，讲者认为这类做法可以用于论文。
- **讲述提醒：** 保留讲者对示例的说明；不对图表质量或投稿适用性作独立保证。可在课堂演示中说明数据图和纯生成图的来源区别。

- **讲者经验：** 讲者称示例约用一个小时生成并修改，达到其认为较精美、有设计感的状态。

- **讲述重点：** 展示生成与修改是一个连续过程；讲者的课程 PPT 是示例，不据此推断工具能自动完成所有汇报准备。

## 第七章：论文日报与周报

**本章重点：** 口播稿区分大范围文献调研与周期性论文追踪：讲者不推荐单靠网页 Skill 做大规模调研，但推荐用定时任务持续关注特定方向的新论文。

### 7.1 设置周期性论文追踪

- **口播描述的入口：** 在插件界面的“已安排”区域创建周期任务，也可以通过对话方式设置和调整任务。
- **口播描述的做法：** 指定一个研究方向，让任务每天或每周检索并汇总新论文；不想继续关注原方向时，可通过对话换成其他方向。
- **讲述重点：** 将追踪设置成持续运行的工作流，减少每次手动启动检索的步骤。

### 7.2 阅读每日或每周报告

- **口播示例：** 软体机器人方向的日报，包含当天值得关注的约八篇论文、论文归档链接、研究脉络总结和后续可深入的方向。
- **口播重点：** 报告不只列论文，还尝试帮助读者把新论文放回研究脉络中理解。
- **讲述提醒：** 篇数和报告内容是讲者展示的例子，不设为所有追踪任务的固定格式。

### 7.3 回顾工作流并保留人工把关

- **口播总结的流程：** 可靠管理文献 → 通过问答打磨 Idea 和架构 → 按学科选择写作辅助 → 用 AI 辅助数据分析和绘图 → 将论文转为汇报材料 → 周期性追踪新研究。
- **人工责任：** 讲者强调论文仍需要研究者自己阅读和撰写，亲自判断创新性，并检查 AI 辅助内容和文字是否恰当。
- **结尾落点：** AI 的作用是辅助；研究者对研究问题、论证、文献和最终成果负责。
